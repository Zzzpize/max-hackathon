# Помощник учителя — проверка контрольных в MAX

Мини-приложение и чат-бот в мессенджере MAX для автоматической проверки
математических контрольных работ учеников 2–4 классов.

## Основной пользовательский сценарий

1. Учитель открывает бот в MAX и создаёт работу (тема, задания, эталон).
2. Учитель отправляет фотографии выполненной работы одного ученика.
3. Бот распознаёт ответы, сверяет с эталоном, размечает ошибки и
   формирует объяснение через GigaChat.
4. Учитель открывает мини-приложение, просматривает результат,
   подтверждает или правит оценку одним нажатием.
5. Результат уходит в долгосрочный профиль ученика — система копит
   типичные ошибки и слабые темы.

## Архитектура

```
+---------+     +-----+     +----------+     +-----------+
| MAX bot | --> | Bot | --> | Backend  | --> | GigaChat  |
|         |     | (TS)|     | (Python) |     |   Ultra   |
+---------+     +-----+     +----------+     +-----------+
                                |
                                v
                          +----------+
                          | Postgres |
                          +----------+
                                ^
+------------+                  |
| MAX MiniApp| ----> nginx -----+
| (React)    |
+------------+
```

Три сервиса:
- **backend** — FastAPI + PostgreSQL + GigaChat SDK. Модульная архитектура
  под добавление новых фич (проверка → генерация работ → дашборды).
- **bot** — Node.js + TypeScript. Тонкий клиент MAX Bot API, вся логика
  делегируется в backend.
- **miniapp** — React + Vite + TypeScript. Обслуживается через nginx,
  который также проксирует `/api` в backend.

## Модули backend

- `app/modules/check` — распознавание + сверка + объяснение ошибок (MVP).
- `app/modules/memory` — долгосрочный профиль ученика (MVP).
- `app/modules/generate` — генерация работ по теме (расширение).
- `app/modules/dashboard` — статистика класса (расширение).

Каждый модуль самодостаточен: свои промпты, пайплайн, схемы. Добавление
нового модуля не требует правок в других.

## Локальный запуск

Нужен Docker и Docker Compose.

```bash
cp .env.example .env
# заполнить GIGACHAT_AUTH_KEY, MAX_BOT_TOKEN, MINIAPP_PUBLIC_URL
docker compose up --build
```

Порты по умолчанию:
- `8000` — backend (OpenAPI: `http://localhost:8000/docs`)
- `3000` — bot (webhook приёмник MAX)
- `80` — miniapp (React SPA + `/api` proxy)
- `5432` — postgres (внутренний)

## Переменные окружения

См. `.env.example`. Обязательные:
- `GIGACHAT_AUTH_KEY` — ключ авторизации GigaChat Ultra
- `MAX_BOT_TOKEN` — токен бота от организаторов хакатона
- `MINIAPP_PUBLIC_URL` — публичный HTTPS-URL мини-приложения

## Работа с данными

MVP использует **синтетические работы** для демонстрации. Реальные фото
работ учеников на этапе пилота хранятся на volume `storage_data` в
обезличенном виде: связь `student_id → ФИО` знает только учитель, в БД
хранится хеш идентификатора. Обработка ведётся через GigaChat API
(российская инфраструктура). Согласия родителей — часть пилотного пакета.

## Состав команды и зоны ответственности

- **Frontend + MAX + DevOps** — `miniapp/`, `bot/`, `docker-compose.yml`, инфра

- **PM/Analytics** — `docs/`, `openapi.yaml` (совместно), пилотные метрики

Контракт API — `openapi.yaml` в корне.

## Известные ограничения MVP

- Только математика 2–4 классов, только фото рукописных работ
- Открытые задания (сочинения, развёрнутые ответы) не проверяются
- Оценка выставляется только после подтверждения учителем

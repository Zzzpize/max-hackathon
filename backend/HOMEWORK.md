# Backend модуля «Домашки»

Модуль реализует `06_tz_backend_homework.md`: генерация, хранение,
редактирование, регенерация и экспорт домашних заданий. Фильтры по
предмету/классу/теме и `with_answers=false` также поддерживаются.

## Устройство

- `app/models/homework.py` — независимая таблица `homeworks`, без внешних
  ключей к ученикам, контрольным, проверкам или учебным планам.
- `migrations/versions/0005_homeworks.py` — миграция после `0004_roadmaps`.
  При запуске backend существующий Dockerfile выполняет `alembic upgrade head`.
- `app/modules/generate/core.py` — общий `generate_tasks`: предметный
  системный промпт, один запрос GigaChat и проверка структуры результата.
- `app/modules/homework/pipeline.py` — одна повторная попытка при ошибке
  модели, затем HTTP 502. Возвращает ORM-объект без записи в БД.
- `app/routers/homework.py` — авторизация, проверка владельца и транзакции.
- `app/modules/homework/export.py` — UTF-8 TXT и A4 PDF через ReportLab,
  который уже используется в модуле учебных планов.

`generate_work` вызывает тот же движок, сохраняя прежние ограничения для
математики 2–4 классов, коротких ответов и размеров чисел. После двух
неудачных попыток или без credentials контрольные сохраняют прежнюю
резервную генерацию. Домашки при ошибке возвращают 502.

## Контракт и поведение

Полный контракт находится в `../openapi.yaml`; схема работающего сервиса —
`/docs`. Авторизация всех операций, включая экспорт:

- MiniApp: `X-Init-Data`.
- Бот: `Authorization: Bearer <MAX_BOT_TOKEN>` и `X-Teacher-Id`.

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/homework` | Генерация и сохранение, 201 |
| GET | `/homework` | Список текущего учителя с фильтрами и пагинацией |
| GET | `/homework/{id}` | Одна домашка |
| PATCH | `/homework/{id}` | Изменение `title`, `notes`, `tasks` |
| POST | `/homework/{id}/regenerate` | Замена задач в существующей записи |
| DELETE | `/homework/{id}` | Удаление, 204 без тела |
| GET | `/homework/{id}/export?format=txt\|pdf` | Файл для скачивания |

Пример тела создания:

```json
{
  "subject": "algebra",
  "grade": 7,
  "topic": "Линейные уравнения",
  "n_tasks": 3,
  "prompt": "Две простые задачи и одна задача с объяснением решения"
}
```

`title` необязателен. Название по умолчанию — `<тема>, <дд.мм.гггг>`;
длинная тема сокращается только в названии, чтобы сохранить лимит 200 символов.
Валидация допускает все четыре предмета и классы 1–11, как требует Definition
of Done. Промпт адаптирует сложность к классу; типичные диапазоны предметов
в MiniApp при этом задаются существующим `subjects.ts`.

Список сортируется по `updated_at DESC, id ASC`. Фильтр `topic` ищет
подстроку без учёта регистра. Символы `%` и `_` не работают как маски.

В PATCH пропущенное поле не меняется, `notes: null` очищает заметки.
`tasks` заменяется целиком: 1–30 задач, номера от 1 без повторов и пропусков.
Условие и ответ обязательны. Если `difficulty` задан, допустимы только
`easy`, `medium`, `hard`. `title: null`, `tasks: null` и пустой PATCH дают 422.

Регенерация принимает `{ "extra_prompt": "Сделай сложнее" }` или пустое тело.
Использует сохранённые предмет, класс, тему, исходный запрос и текущее число
задач, включая ручные правки. Дополнительный запрос действует на эту генерацию.
`id`, название, заметки и дата создания сохраняются. При неудаче задачи и
`updated_at` остаются прежними.

Чужая домашка даёт 403, отсутствующая — 404, отсутствие авторизации — 401.

## Экспорт и интеграция с MiniApp

По умолчанию оба формата содержат задания и отдельный блок ответов для учителя.
В PDF ответы начинаются с новой страницы; после каждой задачи оставлены четыре
строки для решения. `with_answers=false` исключает ответы. Заметки и исходный
запрос учителя в файлы не попадают. Дата в документе — дата экспорта.

`Content-Disposition` содержит ASCII `filename` и UTF-8 `filename*` для названия
с кириллицей. В Docker уже установлен DejaVu Sans для отображения кириллицы.

**Существующие ссылки `<a href={api.homeworkExportUrl(...)}>` в MiniApp не
передают `X-Init-Data` и получают 401.** Фронтенду нужно скачивать файл через
`fetch` с теми же заголовками, что у остальных API-запросов, а затем сохранять
полученный Blob. Это не требует изменения API или передачи credentials в URL.
Frontend и бот в рамках этого backend-ТЗ не изменялись.

## Проверка

Из каталога `backend` в Linux или WSL:

```bash
python -m pip install -r requirements-dev.txt
DATABASE_URL=sqlite+aiosqlite:///:memory: python -m pytest -q
```

Linux требуется существующему модулю `student_names.py`, использующему `fcntl`.
Тесты изолируют БД через SQLite и подменяют только обращения к LLM; ключи
GigaChat и доступ к MAX не требуются. PDF проверяются извлечением текста,
размером страницы, переносами и отделением ответов.

Для проверки миграции на PostgreSQL используйте тестовую БД и команды
`alembic upgrade head`, `alembic current`. Миграция поддерживает откат до
`0004_roadmaps`; откат удаляет таблицу домашних заданий.

Качество реальных заданий требует отдельного прогона с рабочими credentials
GigaChat: моки проверяют контракт и обработку ошибок, а не предметную точность.
